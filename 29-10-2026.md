## q1

### Problem Overview: Linked List Cycle (LeetCode 141)
Given `head`, the head of a singly linked list, determine if the linked list has a cycle in it. There is a cycle in a linked list if there is some node in the list that can be reached again by continuously following the `next` pointer.

---

### How to Approach the Problem

#### Approach 1: Hash Set / Visited Set (Brute Force / Auxiliary Memory)
1. **Intuition**:
   - Traverse the linked list starting from `head`.
   - Store every visited node reference/object in a `set()`.
   - Before moving to `current.next`, verify if `current in visited`.
   - If a node is already present in `visited`, a cycle exists -> return `True`.
   - If `current` reaches `None`, the list terminates -> return `False`.
2. **Critical Teaching Point (Node Identity vs Value)**:
   - Always store the node object/reference (`id(current)`), **never** just `current.val`. Multiple distinct nodes can have the same value without creating a cycle.
3. **Trade-offs**:
   - **Time Complexity**: O(n)
   - **Space Complexity**: O(n) (undesirable when memory is constrained).

---

#### Approach 2: Floyd's Cycle-Finding Algorithm (Tortoise and Hare / Slow & Fast Pointers)
1. **Core Intuition**:
   - Imagine two runners on a running track. If the track is straight (linear list), the faster runner simply reaches the finish line (`None`). If the track has a circular loop (cycle), the faster runner will eventually lap the slower runner from behind and they will collide.
2. **Pointer Mechanics**:
   - `current` (Slow pointer): Advances **1 step** per iteration (`current = current.next`).
   - `skip` (Fast pointer): Advances **2 steps** per iteration (`skip = skip.next.next`).
3. **Mathematical Proof of Collision**:
   - Let the distance between `skip` and `current` inside a cycle of length C be d steps.
   - In each iteration:
     - `skip` moves +2 steps forward.
     - `current` moves +1 step forward.
     - The gap between them changes by (2 - 1) = 1 step.
   - Because the relative speed is strictly 1 step per tick, the distance decreases smoothly:
     `d -> d - 1 -> d - 2 -> ... -> 0`
   - The fast pointer can **never leap over** the slow pointer without landing on the exact same node!
4. **Walkthrough of Session Example**:
   - Consider a linked list with values: `3 -> 4 -> 5 -> 6 -> 7 -> 8 -> 9 -> 10 -> 17 -> 1 -> 2 -> (loops back to 5)`.
   - `skip` enters the cycle first and begins orbiting.
   - `current` enters the cycle at node `5`.
   - With every step, `skip` closes the gap by 1 node until `current == skip`, confirming the cycle.
5. **Edge Cases**:
   - Empty list (`head is None`) or single node without cycle (`head.next is None`): The `while skip and skip.next` condition evaluates to `False` immediately, safely returning `False`.
   - Guard condition: Always verify both `skip` and `skip.next` before attempting `skip.next.next` to avoid `AttributeError: 'NoneType' object has no attribute 'next'`.

---

### Python Code

```Python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, x):
#         self.val = x
#         self.next = None

class Solution:
    # TC: O(n), SC: O(n)
    # def hasCycle(self, head: Optional[ListNode]) -> bool:
    #     visited = set()
    #     current = head

    #     while current:
    #         if current in visited:
    #             return True
    #         visited.add(current)
    #         current = current.next
    
    #     return False

    # TC: O(n), SC: O(1)
    def hasCycle (self, head: Optional[ListNode]) -> bool:
        current = head
        skip = head
        # 3,4,5,6,7,8,9,10,17,1,2(5)
        while skip and skip.next:
            current = current.next
            skip = skip.next.next
            if current == skip:
                return True

        return False
```

### Complexity Analysis
- **Time Complexity**: O(n)
  - *No Cycle*: Fast pointer reaches the end in n / 2 steps -> O(n).
  - *Cycle Present*: If non-cyclic part has length k and cycle has length C, fast pointer enters cycle in k steps. Within at most C iterations, fast catches slow. Total steps <= k + C = n -> O(n).
- **Space Complexity**: O(1) auxiliary space (only two pointer references maintained).

## q2

### Problem Overview: LRU Cache (LeetCode 146)
Design a data structure that follows the constraints of a **Least Recently Used (LRU) Cache**.

Implement the `LRUCache` class:
- `LRUCache(int capacity)`: Initialize the LRU cache with positive size `capacity`.
- `int get(int key)`: Return the value of the `key` if the key exists, otherwise return `-1`.
- `void put(int key, int value)`: Update the value of the `key` if the `key` exists. Otherwise, add the `key-value` pair to the cache. If the number of keys exceeds the `capacity` from this operation, **evict the least recently used key**.

**Requirement**: Both `get` and `put` must run in O(1) average time complexity.

---

### Why Single Data Structures Fall Short
1. **Hash Map alone**: Provides O(1) lookup, but does not maintain the temporal ordering (recency) of elements.
2. **Array / List alone**: Maintains order, but removing or repositioning an item requires O(n) shifting.
3. **Singly Linked List**: Can insert at ends in O(1), but deleting an arbitrary node in the middle requires traversing to find its predecessor (O(n)).

### The Architecture: Hash Map + Doubly Linked List (DLL)
To achieve O(1) for all operations, we combine two data structures:
1. **Hash Map (`self.cache`)**: Maps `key -> Node`. Gives O(1) instant direct access to the memory address of any node in the list.
2. **Doubly Linked List (DLL)**:
   - Each node contains `key`, `val`, `prev`, and `next`.
   - Given a pointer to a node, a DLL allows unlinking (`remove`) in O(1) without scanning the list:
     ```
     prev_node <---> node <---> next_node
     prev_node <---------------> next_node
     ```
   - Inserting a node before or after a known boundary takes O(1).

---

### Design Convention & Sentinel (Dummy) Nodes
*(As taught with reference to the accompanying session notes in `lru_cache_explanation.pdf`)*

```
         (Least Recent)                                  (Most Recent)
   None <--- [head: (0,0)] <=======> ... <=======> [tail: (0,0)] ---> None
                   ^                                    ^
                   |                                    |
            LRU eviction node                    Insert new nodes here
            (head.next)                          (before tail)
```

- **Sentinel Nodes**: Using dummy `head` and `tail` eliminates null-check edge cases when inserting into an empty list or deleting the only element.
- **Convention**:
  - `self.head`: Boundary marker for the **Least Recently Used (LRU)** elements.
  - `self.tail`: Boundary marker for the **Most Recently Used (MRU)** elements.
  - **`remove(node)`**: Unlinks `node` from anywhere between `head` and `tail`.
  - **`insert(node)`**: Inserts `node` right before `tail` (making it the most recently accessed).

---

### Step-by-Step Method Mechanics

#### 1. `get(key)`
1. Check if `key in self.cache`:
   - If **found**:
     - Retrieve `node = self.cache[key]`.
     - Refresh its recency: `self.remove(node)` then `self.insert(node)` (moves node to right before `tail`).
     - Return `node.value`.
   - If **not found**:
     - Return `-1`.

#### 2. `put(key, value)`
1. If `key in self.cache`:
   - Remove the existing outdated node: `self.remove(self.cache[key])`.
2. Create `new_node = Node(key, value)`.
3. Add to hash map: `self.cache[key] = new_node`.
4. Insert into DLL: `self.insert(new_node)` (before `tail`).
5. **Capacity Check**:
   - If `len(self.cache) > self.capacity`:
     - Identify LRU candidate: `lru_node = self.head.next`.
     - Unlink from list: `self.remove(lru_node)`.
     - Delete from dictionary: `del self.cache[lru_node.key]`.

### Python Code

```Python
class Node:
    def __init__(self, key, val):
        # act as self.data
        self.key = key
        self.value = val

        self.next = None
        self.prev = None

class LRUCache:

    def __init__(self, capacity: int):
        self.capacity = capacity
        self.cache = {}

        # The convention can be changed
        self.head = Node(0,0) # Least Recent
        self.tail = Node(0,0) # Most Recent
        self.head.next = self.tail
        self.tail.prev = self.head

    def remove(self, node):
        prev_node = node.prev
        next_node = node.next
        prev_node.next = next_node
        next_node.prev = prev_node

    def insert(self, node):
        prev_node = self.tail.prev
        next_node = self.tail
        prev_node.next = node
        next_node.prev = node
        node.next = next_node
        node.prev = prev_node

    def get(self, key: int) -> int:
        if key in self.cache:
            node = self.cache[key]
            self.remove(node)
            self.insert(node)
            return node.value
        return -1

    def put(self, key: int, value: int) -> None:
        if key in self.cache:
            self.remove(self.cache[key])
        new_node = Node(key, value)
        self.cache[key] = new_node
        self.insert(new_node)
        if len(self.cache) > self.capacity:
            lru_node = self.head.next
            self.remove(lru_node)
            del self.cache[lru_node.key]

# Your LRUCache object will be instantiated and called as such:
# obj = LRUCache(capacity)
# param_1 = obj.get(key)
# obj.put(key,value)
```

### Complexity Analysis
- **`get(key)`**: O(1) time (dictionary hash lookup + O(1) DLL pointer manipulation).
- **`put(key, value)`**: O(1) time (dictionary insertion/deletion + O(1) DLL node insertion/removal).
- **Space Complexity**: O(capacity) since the hash map and doubly linked list store at most `capacity + 1` nodes at any instant.

## q3

### Problem Overview: LRU Cache using Python's `collections.OrderedDict`
Python's standard library provides `collections.OrderedDict`, an ordered dictionary that combines a hash table with an underlying doubly linked list in C.

---

### How to Approach with `OrderedDict`
1. **Order Retention**:
   - In standard Python 3.7+, regular `dict` preserves insertion order, but lacks efficient O(1) reordering and bidirectional popping methods.
   - `OrderedDict` provides two specialized O(1) primitives:
     - `self.cache.move_to_end(key)`: Moves an existing key to the right end (MRU position) in O(1).
     - `self.cache.popitem(last=False)`: Pops the key-value pair from the left end (LRU position in FIFO order) in O(1).
2. **Operation Mapping**:
   - **`get(key)`**: If key is missing, return `-1`. Otherwise, mark as most recently used via `move_to_end(key)` and return the value.
   - **`put(key, value)`**: If key already exists, move it to end via `move_to_end(key)`. Assign `cache[key] = value`. If size exceeds capacity, call `popitem(last=False)` to drop the oldest entry.

---

### Comparison: Manual DLL vs `collections.OrderedDict`
| Feature | Manual Doubly Linked List + Dict (q2) | Python `collections.OrderedDict` (q3) |
|---|---|---|
| **Underlying Mechanism** | Custom `Node` objects with explicit pointers | C-level doubly linked list + hash table |
| **Code Length** | ~50 lines | ~20 lines |
| **Interview Suitability** | Highly Recommended (Tests core data structure & pointer skills) | Great as a follow-up or in practical software engineering |
| **Time Complexity** | O(1) for `get` and `put` | O(1) for `get` and `put` |
| **Space Complexity** | O(capacity) | O(capacity) |

---

### Python Code

```Python
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity: int):
        self.cache = OrderedDict()
        self.capacity = capacity

    def get(self, key: int) -> int:
        if key not in self.cache:
            return -1
        self.cache.move_to_end(key)
        return self.cache[key]

    def put(self, key: int, value: int) -> None:
        if key in self.cache:
            self.cache.move_to_end(key)
        self.cache[key] = value
        if len(self.cache) > self.capacity:
            self.cache.popitem(last=False)

# Your LRUCache object will be instantiated and called as such:
# obj = LRUCache(capacity)
# param_1 = obj.get(key)
# obj.put(key,value)
```

### Complexity Analysis
- **`get(key)`**: O(1) average time.
- **`put(key, value)`**: O(1) average time.
- **Space Complexity**: O(capacity) storing at most `capacity` entries.
