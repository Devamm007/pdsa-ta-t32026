## q1

### Problem Overview: Cheapest Flights Within K Stops (LeetCode 787)
There are `n` cities connected by some number of flights. You are given an array `flights` where `flights[i] = [fromi, toi, pricei]` indicates that there is a flight from city `fromi` to city `toi` with cost `pricei`.

Given three integers `src`, `dst`, and `k`, return the cheapest price from `src` to `dst` with at most `k` stops. If there is no such route, return `-1`.

---

### How to Approach the Problem
*(Notes from `rough_w5_shortest-path-algos_code.pdf` and `rough_w5_shortest-path-algos.pdf`)*

The restriction "at most `k` stops" means our path can take at most **`k + 1` edges (flights)**:
- 0 stops = 1 edge (direct flight)
- 1 stop = 2 edges
- `k` stops = `k + 1` edges

Standard Dijkstra is greedy on total cost, which doesn't guarantee finding the cheapest path within the limited number of stops without extra state tracking. We discussed two simple ways to solve this:

---

#### Approach 1: Level-by-Level BFS (Queue + Distance Pruning)
1. **Building the Graph**:
   - Construct an adjacency list where each node points to `(neighbor, price)`.
   - Discussed a few ways to write this in Python:
     ```python
     # Using setdefault
     adj_l = dict()
     for u, v, price in flights:
         adj_l.setdefault(u, []).append((v, price))
     ```
2. **Queue Traversal**:
   - Queue elements store `(current_node, current_cost)`.
   - Maintain a `min_cost` array initialized to `float('inf')` with `min_cost[src] = 0`.
   - Each level of the BFS corresponds to taking 1 flight.
   - We only add a neighbor to the queue if `cost + price < min_cost[neighbor]`. This prunes redundant explorations.
3. **Stopping Condition**:
   - Stop processing once `min_stops > k` or the queue runs empty.

---

#### Approach 2: Bellman-Ford Variant (Relaxation with Step Limit)
1. **Intuition**:
   - Regular Bellman-Ford relaxes edges `V - 1` times.
   - Because we can make at most `k` stops (`k + 1` flights), we only run the outer relaxation loop **`k + 1` times**.
2. **Important Detail (`prices.copy()` vs in-place update)**:
   - When relaxing edges in round `i`, we must read from the previous round's prices:
     ```python
     temp_prices = prices.copy()
     for u, v, price in flights:
         if prices[u] != float('inf'):
             if prices[u] + price < temp_prices[v]:
                 temp_prices[v] = prices[u] + price
     prices = temp_prices
     ```
   - **Why this matters**: If we update `prices` directly in-place, an edge relaxed earlier in the loop could immediately be used to relax another edge in the same pass. That would allow paths with more edges than the current iteration count allows.

3. **Session Walkthrough Example**:
   - Graph: 
     - `0 -> 1` (100)
     - `0 -> 2` (100)
     - `1 -> 2` (100)
     - `1 -> 3` (600)
     - `2 -> 3` (200)
     - `src = 0`, `dst = 3`, `k = 1`
   - Trace:
     - Start: `prices = [0, inf, inf, inf]`
     - Round 1 (0 stops / 1 flight):
       - `prices = [0, 100, 100, inf]`
     - Round 2 (1 stop / 2 flights):
       - From 1: `1 -> 3` gives `100 + 600 = 700`
       - From 2: `2 -> 3` gives `100 + 200 = 300`
       - Min cost to node 3 becomes `300` (`prices[2] + 200 < temp_prices[3]`).
       - Result: `300` via path `0 -> 2 -> 3`.

---

### Python Code

```Python
from collections import deque

class Solution:
    # Method 1: Level-by-level BFS with queue
    def findCheapestPrice(self, n: int, flights: list[list[int]], src: int, dst: int, k: int) -> int:
        adj_l = dict()
        for u, v, price in flights:
            adj_l.setdefault(u, []).append((v, price))

        queue = deque([(src, 0)])

        min_cost = [float('inf')] * n
        min_cost[src] = 0

        min_stops = 0

        while min_stops <= k and queue:
            for _ in range(len(queue)):
                curr, cost = queue.popleft()
                for v, price in adj_l.get(curr, []):
                    new_cost = cost + price
                    if new_cost < min_cost[v]:
                        min_cost[v] = new_cost
                        queue.append((v, new_cost))
            min_stops += 1

        return min_cost[dst] if min_cost[dst] != float('inf') else -1

    # Method 2: Bellman-Ford variant
    def findCheapestPrice_BellmanFord(self, n: int, flights: list[list[int]], src: int, dst: int, k: int) -> int:
        prices = [float('inf')] * n
        prices[src] = 0

        # At most k stops means at most k + 1 flights
        for _ in range(k + 1):
            temp_prices = prices.copy()
            for u, v, price in flights:
                if prices[u] != float('inf'):
                    if prices[u] + price < temp_prices[v]:
                        temp_prices[v] = prices[u] + price
            prices = temp_prices

        return prices[dst] if prices[dst] != float('inf') else -1
```

### Complexity Analysis
- **Method 1 (BFS)**:
  - **Time Complexity**: O(k * E) in the worst case, as we only expand paths up to `k + 1` levels.
  - **Space Complexity**: O(V + E) for the adjacency list and queue.
- **Method 2 (Bellman-Ford)**:
  - **Time Complexity**: O(k * E), running `k + 1` passes over all `E` flights.
  - **Space Complexity**: O(V) for the price arrays.

## q2

### Problem Overview: Path with Maximum Probability (LeetCode 1514)
You are given an **undirected weighted graph** of `n` nodes (0-indexed), represented by an edge list where `edges[i] = [a, b]` is an undirected edge connecting nodes `a` and `b` with a probability of success `succProb[i]`.

Given two nodes `start_node` and `end_node`, find the path with the maximum probability of success to go from `start_node` to `end_node`. If there is no path, return `0.0`.

---

### How to Approach the Problem
*(Notes from `rough_w5_shortest-path-algos_code.pdf`)*

Instead of adding edge weights to find a minimum sum, here probabilities **multiply** along the path:
- `prob(u -> v) = prob[u] * edge_prob`
- Since all probabilities are between 0 and 1, multiplying probabilities makes the product smaller or equal.
- We want to maximize the final probability reaching `end_node`.

---

### Debugging the Session Code (What went wrong and why)
In class, an initial Bellman-Ford attempt gave `0` on the test case:

```
Session test case:
n = 5
edges = [[1, 4], [2, 4], [0, 4], [0, 3], [0, 2], [2, 3]]
succProb = [0.37, 0.17, 0.93, 0.23, 0.39, 0.04]
start_node = 3, end_node = 4
```

1. **Undirected edges were checked in only one direction**:
   - The faulty code only relaxed `u -> v`:
     ```python
     u = e[0]
     v = e[1]
     if temp_mp[u] * succProb[i] > temp_mp[v]:
         temp_mp[v] = temp_mp[u] * succProb[i]
     ```
   - In the input, the edge between 0 and 3 is stored as `[0, 3]`. Here `u = 0, v = 3`.
   - But we start from node 3! The path needs to move `3 -> 0`.
   - Since `temp_mp[0]` was 0, it never propagated probability to node 0, so the whole traversal died out and returned 0.
   - **Fix**: Check both `u -> v` and `v -> u` for each edge.

2. **Loop count and early stopping**:
   - We don't need `len(edges)` iterations; `n` (or `n - 1`) passes are enough for a graph of `n` vertices.
   - If a whole pass runs without updating any probabilities (`updated == False`), we can `break` early.

```Python
# Corrected version: relaxing both directions with early stopping
class Solution:
    def maxProbability(self, n: int, edges: list[list[int]], succProb: list[float], start_node: int, end_node: int) -> float:
        max_probs = [0] * n
        max_probs[start_node] = 1

        for _ in range(n):
            temp_mp = max_probs.copy()
            updated = False

            for i, e in enumerate(edges):
                u = e[0]
                v = e[1]
                prob = succProb[i]

                # Check u -> v
                if temp_mp[u] * prob > temp_mp[v]:
                    temp_mp[v] = temp_mp[u] * prob
                    updated = True

                # Check v -> u (needed because graph is undirected)
                if temp_mp[v] * prob > temp_mp[u]:
                    temp_mp[u] = temp_mp[v] * prob
                    updated = True

            max_probs = temp_mp

            # Early stop if nothing changed this round
            if not updated:
                break

        return max_probs[end_node]
```

### Alternative: Dijkstra (Max-Heap)
We can also use a Max-Heap (`heapq` with negative probabilities) to extract the best probability node at each step. This runs in `O(E log V)`, which is faster on larger graphs.

### Complexity Analysis
- **Time Complexity**: O(V * E) in the worst case for Bellman-Ford, but often terminates much faster thanks to early stopping.
- **Space Complexity**: O(V) for the probabilities array.

## q3

### Problem Overview: Rotting Oranges (LeetCode 994)
You are given an `m x n` `grid` where each cell can have one of three values:
- `0`: Empty cell
- `1`: Fresh orange
- `2`: Rotten orange

Every minute, any fresh orange that is 4-directionally adjacent to a rotten orange becomes rotten.

Return the minimum number of minutes that must elapse until no cell has a fresh orange. If this is impossible, return `-1`.

---

### How to Approach the Problem

#### Intuition: Multi-Source BFS
- All rotten oranges rot their adjacent fresh oranges at the same time every minute.
- Instead of starting BFS from a single node, we put **all initial rotten oranges** into a queue at minute 0.
- Each round of popping the current queue contents corresponds to 1 minute passing.

#### Steps:
1. Scan the grid once:
   - Add all initial rotten orange positions `(r, c)` to `queue`.
   - Count how many fresh oranges exist (`fresh_count`).
2. If `fresh_count == 0`, we are already done -> return `0`.
3. While the queue has oranges and `fresh_count > 0`:
   - Pop all current rotten oranges in this level.
   - For each, check 4 neighbors (up, down, left, right).
   - If neighbor is fresh (`1`), make it rotten (`2`), decrement `fresh_count`, and push it into the queue.
   - Increment `minutes += 1`.
4. If `fresh_count == 0`, return `minutes`. If fresh oranges are still left over, return `-1`.

---

### Python Code

```Python
from collections import deque

# 1. Rough idea discussed in session
class SolutionRough:
    def orangesRotting(self, grid: list[list[int]]) -> int:
        m = len(grid)
        n = len(grid[0])

        rot_orange_loc = []
        fresh_orange_loc = []
        for r in range(m):
            for c in range(n):
                if grid[r][c] == 2:
                    rot_orange_loc.append((r, c))
                if grid[r][c] == 1:
                    fresh_orange_loc.append((r, c))

        update = True
        counter = 0
        while update:
            update = False
            # Expand rotten oranges into neighboring fresh ones
            counter += 1

        if len(fresh_orange_loc) == 0:
            return counter - 1
        else:
            return -1


# 2. Complete BFS Implementation
class Solution:
    def orangesRotting(self, grid: list[list[int]]) -> int:
        m, n = len(grid), len(grid[0])
        queue = deque()
        fresh_count = 0

        # Step 1: Collect initial rotten oranges and count fresh ones
        for r in range(m):
            for c in range(n):
                if grid[r][c] == 2:
                    queue.append((r, c))
                elif grid[r][c] == 1:
                    fresh_count += 1

        # If there are no fresh oranges to begin with
        if fresh_count == 0:
            return 0

        minutes = 0
        directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

        # Step 2: BFS level by level
        while queue and fresh_count > 0:
            for _ in range(len(queue)):
                r, c = queue.popleft()
                for dr, dc in directions:
                    nr, nc = r + dr, c + dc
                    if 0 <= nr < m and 0 <= nc < n and grid[nr][nc] == 1:
                        grid[nr][nc] = 2  # rot the orange
                        fresh_count -= 1
                        queue.append((nr, nc))
            minutes += 1

        # Step 3: Check if all fresh oranges were reached
        return minutes if fresh_count == 0 else -1
```

### Complexity Analysis
- **Time Complexity**: O(m * n). We scan the grid initially, and each cell is visited in BFS at most once.
- **Space Complexity**: O(m * n) for the queue in the worst case.
