NeetCode.io GitHub Sync & Avoiding Empty Repositories

Understanding why fresh NeetCode repos start with only a README and how to sync your code solutions.

Why did my repository only have a README.md? (The 23f Guy Issue)

When you enable GitHub Sync on NeetCode.io, NeetCode creates an initial commit containing only a default README.md explaining how sync works. NeetCode only commits your code when you click "Submit" inside their in-browser editor! If you only checked off checkboxes without submitting code in the editor, your GitHub repo remains empty of code files.

Step 1

Enable GitHub Sync in NeetCode

Go to your NeetCode.io Account Settings → Integrations → Connect GitHub. Authorize the integration to create your neetcode-submissions repo.

Step 2

Open Solved Problems in NeetCode Editor

Go to your Roadmap or Practice list on NeetCode. For each problem you already solved (e.g. Contains Duplicate, Two Sum, Group Anagrams), open the problem in the browser.

Step 3

Click "Submit" in the In-Browser Code Editor

Ensure your solution is in the code box and hit Submit. Once accepted, NeetCode immediately commits Data Structures & Algorithms/<problem>/submission-0.py to your GitHub repo!

Step 4

Verify Code Files on GitHub

Open your repository on GitHub. You will now see genuine .py, .cpp, or .java code files under problem directories. Now your repository is fully qualified for the Arena Leaderboard!

The LeetHub v2 Re-Submit Workaround

If you already use LeetHub v2 and don't want to switch extensions, you can backfill your past solutions in minutes:

How the Workaround Works

Zero Re-Coding Required

LeetCode permanently saves your latest accepted code inside the problem editor. You do not need to re-write your code from memory!

  • 1. Go to your LeetCode profile → Submissions tab.
  • 2. Click on any previously accepted problem.
  • 3. LeetCode loads your previously accepted code right in the editor.
  • 4. Hit Submit.
  • 5. LeetHub v2 immediately catches the accepted verdict and creates a git commit in your GitHub repository!

Bulk Historical Export via Python CLI (Power Users)

If you have 100+ historical problems and want to export all code files locally in 30 seconds using an open-source CLI:

Step 1

Install leetcode-export via pip

pip install leetcode-export

A lightweight, open-source Python utility that queries the LeetCode GraphQL API for all your accepted submissions.

Step 2

Run the Bulk Export Script

# Run interactive export tool:
leetcode-export --folder ./my-dsa-solutions

It downloads every accepted solution into clean directories with problem title, code file, and complexity metadata.

Step 3

Push the Solutions to GitHub

cd my-dsa-solutions
git init
git add .
git commit -m "feat: bulk export of past accepted DSA solutions"
git branch -M main
git remote add origin https://github.com/your-username/dsa-challenge.git
git push -u origin main

Creates your GitHub repository with all historical solutions and pushes to GitHub.

Submit Repository to the Arena

Security Best Practices for Browser Extensions & GitHub Sync

  • Never grant full account write access: When generating GitHub Personal Access Tokens (PATs), only grant Contents: Read & Write on the specific repository you want to sync.
  • Never enter your primary GitHub password: Trusted extensions use GitHub OAuth or Personal Access Tokens; they never require passwords.
  • Audit your commits: Check that your repository does not contain .env files, cookies, or personal authorization keys.

Automated Connection vs Manual Git: When to Use Which?

Understand the engineering trade-offs between automated synchronization and manual Git commits.

NeetCode Automated Sync

NeetCode.io Direct GitHub Integration

Connects your NeetCode account directly to a designated GitHub repository via GitHub OAuth.

When to Use:
  • You are focusing 100% on solving problems with zero setup friction.
  • You want every accepted run recorded automatically without switching away from the browser.
  • You practice consistently every day and want automatic daily timestamps.
Caveats:
  • Creates separate files for each attempt (submission-0.py, submission-4.py).
  • Commit messages are generic (e.g. Add: two-integer-sum - submission-0).
LeetCode Extension Sync

LeetSync / LeetHub v2 Browser Extension

A Chrome/Firefox extension that intercepts 'Accepted' responses on LeetCode and commits to your repo.

When to Use:
  • You solve questions directly on LeetCode web editor.
  • You want problem statements and difficulty automatically packaged into a README.md.
  • Ideal for quick contest submissions and daily LeetCode challenges.
Caveats:
  • Requires third-party browser extension permissions.
  • Can generate burst commits that get penalized if you submit 15 problems in 1 hour.
Manual Git Workflow

Manual Stage, Commit & Push

Solving locally in VS Code / IDE and using standard Git CLI commands: git add, git commit, git push.

When to Use:
  • Building an Interview Portfolio: Clean directory structure (e.g., Arrays/, DynamicProgramming/) that looks professional to recruiters.
  • Writing Explanations & Big-O Notes: Documenting time/space complexity, intuition, and edge cases.
  • Multi-Language Solutions: Providing both Python and C++ implementations earns the +5% Polyglot Bonus!
  • Highest Holistic Score: Better documentation and structured commits maximize the Arena score formula!
Recommendation:

Use automated sync for daily speed, but maintain manual structured solutions for your top 50 favorite interview problems!

Step-by-Step Manual Git Command Cheatsheet

Follow these exact 4 steps each day when solving a problem locally:

Step 1

Inspect Your Changes

git status

Shows which files were created or modified in your workspace.

Step 2

Stage Your Solved Problem File

git add 01-arrays/two-sum.py
# Or stage the entire problem folder:
git add 01-arrays/two-sum/

Moves the file into the Git staging area ready for commit.

Step 3

Commit with Semantic Convention & Complexity

git commit -m "feat(arrays): Two Sum - Easy [O(N) Time, O(N) Space]"

Creates a permanent commit with timestamp and difficulty annotation.

Step 4

Push to GitHub

git push origin main

Uploads your commit to GitHub. Then submit or refresh your repo in the Arena!
